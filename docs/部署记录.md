## 三、遇到的五个问题

### 问题 1:22 端口不通,但 sshd 明明在监听

现象:外网连不上 22,控制台 VNC 却能登录。

排查:`sudo ss -ltnp | grep ':22'` 显示 `LISTEN 0.0.0.0:22` —— 服务正常,
那问题就在网络策略层。

根因:这台机器**最初装的是 Windows**(远程桌面走 3389),云防火墙默认规则里
没有 22。重装成 Linux 后规则不会自动补,于是 SSH 被挡在门外。

解决:控制台加 `TCP:22` 和 `TCP:8088` 两条规则。

> 教训:排查要**逐层证明**。先证明服务在听,再证明网络放行,
> 而不是一上来就改 `sshd_config` 重启服务。

### 问题 2:2G 内存编不动这个项目

现象:`docker compose build` 跑到 28% 卡住,日志 6 分钟不动。

排查:`ps` 看到 `cc1plus` 状态 `R`、CPU 87%、**RSS 1.58GB**;
`vmstat` 显示每秒换入 365 页、换出 713 页;可用内存只剩 57MB。

根因:httplib 和 nlohmann/json 都是重模板,单个编译单元峰值 1.5GB 以上。
2 核 2G 机器只能靠 swap 硬撑,陷入换页抖动。加 `-j1` 也救不了,
因为**单个文件就要 1.5GB**。

解决:**本地构建,传镜像**。

```bash
# 本地(20 核,40 秒)
docker compose build app
docker save secguard-app:latest | gzip -1 > /tmp/secguard-image.tar.gz   # 153MB -> 36MB

# 传输(3 秒)
scp /tmp/secguard-image.tar.gz <user>@<host>:/home/<user>/

# 服务器
gunzip -c secguard-image.tar.gz | docker load
docker compose up -d --wait
```

这不是权宜之计,而是 CI/CD 的标准做法:**构建一次,分发产物**。
服务器的职责是运行,不是编译。真要在这台机器上编译,至少需要 4GB 内存。

顺带改了 `docker-compose.yml`:`build.args.BUILD_JOBS` 由
`SECGUARD_BUILD_JOBS` 控制,小内存机器可设 1(提交 4d8c891)。

### 问题 3:github.com 和 Docker 官方仓库不通

现象:`curl https://github.com` 超时,`registry-1.docker.io` 也超时。

解决:
- Docker 本体从**腾讯云镜像源**装:`mirrors.cloud.tencent.com/docker-ce`
- 镜像加速用 `mirror.ccs.tencentyun.com`(腾讯云内网,最快),
  备用 `docker.1panel.live`、`docker.m.daocloud.io`

实测加速器生效:拉 `ubuntu:22.04` 用 **11 秒**。

### 问题 4:自检里"手动触发分析"报 409

现象:自检 1 项失败,`POST /api/analyze/run` 返回 409。

判断:**这是正确行为,不是 bug**。AI 层没启用时,这个接口应该拒绝执行,
而不是假装跑一轮。是我的自检脚本把它当成了失败。

解决:改 `scripts/verify.sh` —— 未启用时期望 409 并算通过;
启用时期望 200。顺带这也成了一条"接口不能一边说没启用一边干活"的检查。

### 问题 5:服务器上没有 wrk,限流测不出来

现象:限流用例跳过。

原因:自检里限流要用并发压测,没有 wrk 时退化成 `xargs + curl`,
并发不够打不空令牌桶。

解决:`apt install wrk`(Ubuntu 22.04 源里有)。装上后限流用例通过
(被限 10765 次)。以后在这台机器上重测性能也用得上。
