## 一、这是什么

一个用 C++20 手写 AC 自动机做核心的 Web 安全审计引擎(WAF)。
放在网站前面,检查每个进来的请求,拦住 SQL 注入 / XSS / 路径穿越 / 命令注入,
把每次检测结果写成审计日志,再把被拦下的记录交给大模型判断真假。

**它和"调个现成库"的项目区别在哪**:核心匹配算法是自己写的,
并且有数据证明它比朴素实现快 52 倍。

## 四、四个能讲的技术点

| 技术点 | 结论 | 数据 |
|---|---|---|
| **手写 AC 自动机** | 特征数 ×5,耗时 ×1.05;朴素实现 ×5.18 | 1000 条特征时快 **52.5 倍** |
| **无锁 MPSC + 批量落库** | 审计异步化 | 比同步写库快 **194 倍**(56371 vs 291) |
| **Redis 共享限流封禁** | 多实例状态一致 | 单机内存的代价:QPS 从 84654 降到 56371(1.5x) |
| **线程数必须 ≥ 连接数** | httplib 是一线程守一连接 | 线程 4→64,P99 从 289ms 降到 6ms |

### 数据口径(重要,别记错)

- 引用**保守下界**:完整检测链路 **36520 QPS / P50 1.57ms / P99 8.29ms**(2 核 64 连接)
- 复测过一轮是 56371 QPS,但**代码没变**,纯粹是机器状态差异(同场景两轮差 40% 是常态)
- 所以对外统一说"3.6 万 QPS",并主动补一句"这是我笔记本上下界,真实值要在目标机器重测"
- **绝对值不可靠,比值可靠** —— 面试优先讲上表里的倍数

## 五、已知局限(主动说,别等人问)

1. LLM 只分析被拦截的记录,规则漏掉的攻击不进队列
2. 限流按 IP,对分散 IP 的慢速攻击不敏感
3. 单机,没做分片;特征库扩到 10 万条内存会到 GB 级
4. WAF 防不住注入,真正的解是参数化查询(本项目 DAO 层已全部用预编译)
5. 特征库是手工整理的 234 条,不是从真实攻击日志挖的
6. 压测走 loopback,没有真实网络损耗
7. 白名单是"路径 + 规则"级,粒度粗
8. 告警通知尽力而为,不保证送达
9. 管理鉴权用用户名名单,改名单要重启
10. 归一化层覆盖编码/分隔符/注释类绕过,覆盖不了**语法等价**(`or 2>1`)和
    **跨字符拆分**(`top['al'+'ert']`、base64)—— 这类要靠 AST/语义分析
11. 评测语料是按已知手法构造的白盒语料,不是真实攻击日志采样;
    "61%"只在这套语料上成立,不能当成线上漏报率

## 十二、2026-10-25 增补:项目 A(绕过评测 + 归一化层)

原来的 228 条特征本质是**子串匹配**,而 `build_scan_text` 对 QUERY/BODY
不做解码(`app_context.cpp:92` 注释写着"原样"). 结果是 `%20` 一编码,
所有含空格的特征(`union select`、`or 1=1`、`order by 1--`)全部失效。

| 引擎改成"原始遍 + 归一化遍"取并集,新增 `MatchResult.canonical_pass` | `include/engine.h`、`src/engine/engine.cpp` |

| 维度 | 样本 | SecGuard | CRS |
|---|---|---|---|
| 基线攻击 | 32 | 32(100%) | 30(93.8%) |

### 顺带修掉的坑 / 发现的坑

1. 归一化**不能剥行注释**:`order by 1--` 这类规则会把 `--` 写进特征本体,
   剥掉就永远命中不了(实测踩到,只有那一条变形漏报)
2. `build_scan_text` 用 `\n` 分段,导致"规范形是否变化"的判断恒真,
   第二遍无条件执行 —— 加了 `may_obfuscate()` 早退扫描后 74/169 条走快路
3. 规则库里 `#`(SQL-033)以 `#` 开头,被加载器当注释跳过,**这条规则从未生效**
4. `select `(带尾空格)被 `trim` 成 `select`,语义从"select 后跟空格"变成
   "出现 select 就拦",贡献 3 条误报
5. 层与层不是独立的:`verify.sh` 那条 `union%20select%201,2,3` 能过,靠的是
   归一化把它还原成 `union select`(BLOCK),因为 `select` 已被降级 ——
   把 `SECGUARD_ENGINE_NORMALIZE=0` 一关,这批编码攻击会从"拦"掉到"只告警"

### 2026-10-27:把上面 3、4 这两类"静默 bug"修彻底

它们共同的性质是:**不报错、不改测试结果,只让"文件写的"和"实际跑的"不一样**。
所以修法不是改几行代码,而是**让这类问题以后能被自动发现**:

| 修了什么 | 怎么修的 |
|---|---|
| 行首 `#` 的规则被当注释吞掉 | 加载时检测「`#` 开头但带 TAB」的行并告警;支持 `\#` 转义表达字面 `#` |
| 特征文本尾空格被静默 trim | 加载时统计并告警(列出前几条);文件里 15 条尾空格已清掉,文件 = 行为 |
| 死规则 SQL-033(`#`) | 删掉。`#` 在 Markdown/CSS/C# 里到处都是,当特征只会制造误报,不值得复活 |
| 规则库体检 | 新增 `waf_eval --lint-rules`:结构性问题(会被静默丢弃/改写)直接让 CI 失败,建议类只提示 |
| `requests_alerted` 重复计数 | 一个请求可能先命中查询串 ALERT、再在请求体命中 BLOCK,钩子里各加一次会两边都涨。改成在 `record_audit` 里按**最终动作**算 |
| `ci-local.sh` 写死 `/home/smb/...` | 改成按脚本位置定位;这个脚本最该支持的恰恰是"换一台机器跑" |
