# 配置清单(单一事实来源)

> 2026-11-05 整理。这个文档回答一个问题:**这个项目的配置到底在哪。**
>
> 结论先说:**不在一个文件夹里**,而且**之前有 36 个参数根本调不动**。
> 现在通过 `env_file` + 一致性检查解决了,下面是完整地图。

---

## 一、配置分五层(为什么不能全塞一个文件夹)

配置不是"放一起就完事",它们的**生命周期和敏感度不一样**,必须分层:

| 层 | 位置 | 特点 | 进版本控制 |
|---|---|---|---|
| **① 代码默认值** | `src/util/config.cpp`、`src/util/config.h`、`src/cache/redis_client.h`、`src/ai/llm_client.h` | 代码不带任何配置也能跑起来 | ✅ |
| **② 部署配置** | **`.env`**(仓库根) | 含密码密钥,每台机器一份 | ❌ gitignore |
| **② 部署配置(文档)** | **`.env.example`** | 和 .env 一一对应的说明 + 默认值 | ✅ |
| **③ 容器编排** | **`docker-compose.yml`** | 容器内部的地址覆盖(服务名/端口/卷/健康检查) | ✅ |
| **④ 运行时可变配置** | `rules/attack_patterns.txt`、`rules/policy.conf`、`rules/allowlist.conf`、`db/schema.sql`、`docker/nginx.conf`、`.github/workflows/ci.yml` | 改完热加载或重启即生效,不需要重建镜像 | ✅ |
| **⑤ 机器级 / 运行态** | 服务器 `~/.admin_password`、`~/.secguard_self_ips`、`~/backups/`、`~/.image-cache/`、**crontab**、`/etc/docker/daemon.json`、`/etc/ssh/sshd_config` | 属于这台机器,不属于代码 | ❌ 不在仓库 |

**本机(E: 盘)的权限要注意一件事**

项目在 `E:\DevEnv\Projects\secguard`,而 WSL 通过 drvfs 挂载 `/mnt/e`,
**挂载参数里没有 `metadata`**,所以 `chmod` 完全无效 —— 权限永远显示 `777`。
真正的访问控制是 **NTFS ACL**。

一开始 `.env` 的 ACL 是从 E: 盘根目录继承来的:

```
Authenticated Users:(I)(M)     <- 任何登录用户可改
BUILTIN\Users:(I)(RX)          <- 任何本地用户可读
```

而这个文件里有数据库口令、JWT 密钥、LLM API Key —— 等于本机任何账号都能读到。
已用下面的命令收紧(去掉继承、只给当前用户):

```powershell
icacls "E:\DevEnv\Projects\secguard\.env" /inheritance:r /grant:r "$env:USERNAME:(F)"
```

收紧后 WSL 与 docker compose 仍能正常读写(实测:WSL 可读 17 行配置、compose 解析通过)。

**为什么 .env 不进版本控制**:里面有 `MYSQL_ROOT_PASSWORD`、`SECGUARD_JWT_SECRET`、
`SECGUARD_DB_PASS`、`SECGUARD_LLM_KEY`。仓库是公开的,泄露等于把管理权限交出去。

**为什么 rules/ 要单独一层**:它随流量变化(见 `docs/演示素材.md` 第九节,
两周扩了 34 条规则)。改规则不该重建镜像,所以 `rules/` 是挂载进容器的只读卷。

## 二、`env_file` 机制:为什么现在改 .env 一定生效

**2026-11-05 之前**用逐条 `environment:` 传变量。代码读 63 个,
compose 只传 41 个 —— **剩下 22 个在容器里永远拿不到**。

这个坑踩过三次才被彻底解决:

| 参数 | 后果 |
|---|---|
| `SECGUARD_AI_MERGE_IPS` | 聚合门槛调不动,查了半小时 |
| `SECGUARD_AUDIT_RETENTION_DAYS` | 保留天数调不动,**结果把最有价值的攻击证据删了** |
| `SECGUARD_THREADS`、`SECGUARD_TOKEN_TTL`、`SECGUARD_REDIS_PASS`、`SECGUARD_AUDIT_ASYNC`、`SECGUARD_REPLAY_REQUIRE`、`SECGUARD_LOGIN_FAIL_LIMIT` … 等 20 多个 | 一直没被发现 |

**现在**:app 服务用了 `env_file: .env`

```yaml
    env_file:
      - .env
    environment:          # 只放"容器内部才有意义"的覆盖
      SECGUARD_DB_HOST: mysql
      SECGUARD_REDIS_HOST: redis
      SECGUARD_BIND: 0.0.0.0
      SECGUARD_PORT: "8080"
      SECGUARD_TRUST_PROXY: "1"
```

- `.env` 里**任何**变量都会自动进容器 → 新增开关不需要再改编排文件
- `environment:` 优先级更高,负责宿主机上不成立的值(服务名、内部端口)
- 代价:`.env` 里的 `MYSQL_ROOT_PASSWORD` 也会进 app 容器环境。app 不读它,
  但能 exec 进容器的人看得到。这台机器只有自己登,可以接受;要严格隔离应拆成
  `app.env` / `db.env` 两个文件。

## 三、常用操作:改什么该动哪个文件

| 我想做的事 | 改哪里 | 怎么生效 |
|---|---|---|
| 调限流速率 / 封禁阈值 | `.env` 的 `SECGUARD_RATE_PER_SEC` 等 | `docker compose up -d app` |
| 调审计保留天数 | `.env` 的 `SECGUARD_AUDIT_RETENTION_DAYS` | 同上 |
| **加/改攻击规则** | `rules/attack_patterns.txt` | `POST /api/rules/reload` **或** 60 秒内自动热加载(不用重启) |
| 把某条规则降级成只告警 | `rules/policy.conf` 加 `规则ID ALERT` | 同上 |
| 加白名单 | `rules/allowlist.conf` | 同上(热加载会一起看) |
| 调 AI 分析频率/模型 | `.env` 的 `SECGUARD_AI_*`、`SECGUARD_LLM_*` | `docker compose up -d app` |
| 换对外端口 | `.env` 的 `SECGUARD_HTTP_PORT` | `docker compose up -d nginx` |
| 改表结构 | `db/schema.sql`(**只在新建库时生效**) | 已存在的库要手工 `ALTER` |
| 改 nginx 反代行为 | `docker/nginx.conf` | `docker compose restart nginx` |
| 改 CI 检查项 | `.github/workflows/ci.yml` | push 即触发 |
| 改备份时间/保留 | `crontab -e`、`scripts/backup-db.sh` 的 `KEEP_DAYS` | cron 到点生效 |
| 改 docker 镜像源 | `/etc/docker/daemon.json` | `systemctl restart docker` |

## 四、敏感文件与权限要求

| 文件 | 权限 | 要求 |
|---|---|---|
| `.env` | **600** | 含密码密钥。服务器上已是 `-rw-------` |
| 服务器 `~/.admin_password` | **600** | 管理员口令 |
| 服务器 `~/backups/` | **700** | 全库数据,含口令哈希 |
| 服务器 `~/.secguard_self_ips` | 644 可接受 | 只存"自己人"的公网 IP,无密钥 |
| `~/.ssh/secguard_ed25519` | **600** | 服务器 + GitHub 认证密钥 |

> **已知问题**:本地 WSL 里的 `.env` 是 `-rwxrwxrwx`(777)。
> 服务器上是 600,本地因为单人使用影响小,但应该改成 600 —— 见第六节。

## 五、两个检查工具(防止这类问题再来第四次)

### `scripts/check-config-sync.sh`

对比三份清单,发现不一致就返回 1:

```bash
./scripts/check-config-sync.sh
```

它查三件事:
- **A** `.env` 里设了但代码根本不读 → 多半是名字拼错
- **B** 代码读但 `.env.example` 没写 → 使用者不知道有这个开关
- **C** code 读的变量能不能到达容器(有 `env_file` 就 Pass)

已挂进 CI 和本地自检,以后再漏一个变量会直接红。

### `scripts/show-config.sh`

从**运行中的容器**里读实际生效的配置(密钥自动打码):

```bash
./scripts/show-config.sh              # 全部
./scripts/show-config.sh --diff       # 只看和默认值不同的
./scripts/show-config.sh --secrets    # 连密钥一起看(慎用)
```

想知道"现在到底跑的是什么参数",一条命令就够,不用翻六个文件。
