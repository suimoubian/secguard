# 上线清单

从"刚买完服务器"到"浏览器能打开",照着勾。

预计 40-60 分钟,其中一半时间在校验和等待。

> **已经跑过一次了。** 实际过程、遇到的五个问题和最终结果见
> [部署记录.md](部署记录.md)。这份清单已按实战结果修正,
> 下面标「实战」的地方就是清单原本没想到、踩了才知道的。
>
> 最重要的修正:**2G 内存的机器不要在上面编译**,见第三部分第 3 步。

## 第一部分:云控制台(约 15 分钟)

### 1. 实名认证

腾讯云买机器前必须实名(身份证 + 人脸)。没做的话购买页会拦你。

### 2. 选套餐

新用户先走特惠页,比列表价便宜一个数量级:

- 特惠活动:<https://cloud.tencent.com/act/pro/lhsale>
- 免费试用:<https://cloud.tencent.com/act/free/personal>
- 常规购买:<https://buy.cloud.tencent.com/lighthouse>

选配要求:

| 项 | 要求 | 说明 |
|---|---|---|
| CPU/内存 | 2核2G 起,4核4G 更好 | SecGuard 全套只吃约 150MB,2G 够跑 |
| 系统盘 | ≥ 40GB | 镜像占 1.2GB,数据库 7 万条审计才 12MB |
| 地域 | 离你近的(上海/北京/广州) | 延迟低 |
| 镜像 | **Ubuntu 22.04 LTS** | 别选 CentOS/Debian,部署脚本按 22.04 写的 |
| 时长 | 1 个月试用或 1 年 | 试用到期数据会被释放,注意 |

### 3. 重置密码

控制台 → 实例 → 更多 → 重置密码。设一个强密码,**记下来**。

（也可以上传 SSH 密钥,但密码更省事。）

### 4. 开放防火墙端口 ← 最容易漏的一步

腾讯云轻量的防火墙**默认只开 22 和几个常用端口**,你在系统里 `ufw allow` 是没用的,
必须在控制台加规则。

控制台 → 实例 → 防火墙 → 添加规则:

| 端口 | 协议 | 用途 |
|---|---|---|
| 22 | TCP | SSH(默认已开) |
| 8088 | TCP | SecGuard 对外端口 |
| 80 | TCP | 可选(以后用域名时) |

**不做这一步,你会遇到:服务在跑、机器上 curl 通、外网连不上。**

### 5. 记下公网 IP

控制台首页就有,形如 `139.199.x.x`。

先测一下通不通:

```bash
# 在你自己的电脑上
ping 139.199.x.x
ssh root@139.199.x.x
```

## 第二部分:机器准备(约 15 分钟)

连上机器后按顺序做。

### 1. 确认系统版本

```bash
lsb_release -a        # 应为 Ubuntu 22.04.x
free -h               # 看内存
df -h /               # 看磁盘
nproc                 # 看核心数
```

### 2. 加 2GB swap ← 2G 内存的机器必做

编译 C++ 时单个 g++ 进程峰值能到 1GB。没有 swap 的话,
构建阶段会被 OOM killer 杀掉,报错还很难看懂(就一句 `Killed`)。

```bash
sudo fallocate -l 2G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
free -h               # 确认 Swap 那一行不是 0
```

### 3. 装 Docker

```bash
curl -fsSL https://get.docker.com | sudo sh
sudo usermod -aG docker $USER
newgrp docker          # 或者退出重登,让用户组生效
docker --version
docker compose version
```

### 4. 配镜像加速(国内必做)

不配的话拉 `ubuntu:22.04` 和 `mysql:8.0` 会非常慢甚至超时。

```bash
sudo mkdir -p /etc/docker
sudo tee /etc/docker/daemon.json <<'EOF'
{
  "registry-mirrors": [
    "https://docker.m.daocloud.io",
    "https://docker.1panel.live"
  ]
}
EOF
sudo systemctl restart docker
docker info | grep -A2 'Registry Mirrors'
```

### 5. 校时(容器和数据库对时间敏感)

```bash
sudo timedatectl set-timezone Asia/Shanghai
timedatectl             # 确认时区和时间正确
```

## 第三部分:部署(约 10 分钟)

### 1. 把代码弄上去

**方式 A:git clone(推荐)**

```bash
# 如果你把仓库推到了 GitHub/Gitee
git clone <你的仓库地址> secguard
cd secguard
```

**方式 B:从本机传**

```bash
# 在你自己的电脑上(WSL 里)
cd /home/smb/projects/secguard
tar --exclude=.git --exclude=build --exclude=.env -czf /tmp/sg.tar.gz .
scp /tmp/sg.tar.gz root@139.199.x.x:/root/
```

```bash
# 在服务器上
cd /root && mkdir -p secguard && tar -xzf sg.tar.gz -C secguard && cd secguard
```

### 2. 生成配置

```bash
cp .env.example .env
```

改掉三个秘密(每个都用 `openssl rand -base64 48` 生成):

```bash
# 生成三个不同的密钥
openssl rand -base64 48   # -> SECGUARD_JWT_SECRET
openssl rand -base64 24   # -> SECGUARD_DB_PASS
openssl rand -base64 24   # -> MYSQL_ROOT_PASSWORD
```

用 `nano .env` 或 `vim .env` 填进去。**同时**把 `MYSQL_ROOT_PASSWORD`
和 `SECGUARD_DB_PASS` 对应到 mysql 服务那边的变量(compose 文件里有说明)。

其他要确认的:

```bash
SECGUARD_HTTP_PORT=8088          # 对外端口,要和防火墙开的端口一致
SECGUARD_ADMIN_USERS=admin       # 管理员用户名,留空则管理接口全关
SECGUARD_AI_ENABLE=0             # 没有 LLM Key 就先关掉
SECGUARD_BUILD_JOBS=2            # 2G 内存设 1;但更建议别在服务器上编译(见下)
```

### 3. 构建 —— 【实战】2G 的机器**不要**在这里编译

原计划是在服务器上 `docker compose build`。实战发现**2G 内存编不动**:

- 单个 `cc1plus` 峰值 **1.58GB**(httplib + nlohmann/json 在同一个编译单元里)
- 编到 28% 就陷入 swap 抖动,6 分钟零进展
- `vmstat` 显示每秒换入 365 页、换出 713 页,可用内存只剩 57MB
- 加 `-j1` 也没用,因为**单个文件就要 1.5GB**

正确做法是**本地构建、传镜像**(这也是 CI/CD 的标准做法):

```bash
# ① 本地(有 8 核以上就够,这里 20 核用了 40 秒)
docker compose build app
docker save secguard-app:latest | gzip -1 > /tmp/sg-image.tar.gz   # 153MB -> 36MB

# ② 传到服务器(实测 3 秒)
scp /tmp/sg-image.tar.gz ubuntu@<服务器IP>:~/

# ③ 服务器上加载并启动
gunzip -c ~/sg-image.tar.gz | sudo docker load
cd ~/secguard && sudo docker compose up -d --wait
```

要点:镜像名必须是 `<compose项目名>-<服务名>`,也就是 `secguard-app`,
`docker load` 之后 compose 会直接用它,不会再尝试构建。

**如果坚持要在服务器上编**:至少 4GB 内存,或者 2GB 内存 + 4GB swap
并接受 30 分钟以上。不建议。

### 4. 启动后先装个 wrk 【实战】

自检脚本里的限流用例要并发压测。没有 wrk 时会退化成 `xargs + curl`,
并发不够、打不空令牌桶,限流那一项会被跳过。

```bash
sudo apt-get install -y wrk     # Ubuntu 22.04 源里有
```

### 5. 启动

```bash
./docker/deploy.sh
```

脚本会:检查前置条件 → 启动 → **轮询健康检查直到通过**。

看到 "部署完成" 就行。

> 注意:如果镜像是本地传过来的,跳过脚本里的构建步骤(脚本会检测已有镜像)。

### 6. 验证

```bash
# 机器上
curl -s http://127.0.0.1:8088/health | head -c 300

# 完整自检(49 项)
./scripts/verify.sh
```

```bash
# 在你自己的浏览器里
http://139.199.x.x:8088/
```

## 第四部分:出问题怎么查

### 浏览器打不开,但机器上 curl 通

99% 是**防火墙没开端口**。回控制台确认 8088 那条规则。

验证方法:

```bash
# 机器上
curl -s http://127.0.0.1:8088/health    # 通
```

```powershell
# 你的电脑上
Test-NetConnection 139.199.x.x -Port 8088    # TcpTestSucceeded 应为 True
```

### 502 Bad Gateway

nginx 连不上 app。按顺序查:

```bash
docker compose ps                       # app 是不是 healthy
docker compose logs --tail=50 app       # 有没有启动报错
```

最常见原因:app 还在等数据库(启动那 10 秒),等一会儿刷新。

### 构建时被 Killed

内存不够。三条一起做:

```bash
free -h                                  # 确认 swap 已启用
docker compose build --build-arg BUILD_JOBS=1
# 还不行就先单独编一次,把 apt 层缓存住
docker compose build --build-arg BUILD_JOBS=1 app
```

### 容器反复重启

```bash
docker compose logs --tail=100 app
docker inspect secguard-app --format '{{.RestartCount}} {{.State.ExitCode}}'
```

`ExitCode=1` 且日志里有"数据库连不上":MySQL 还没起好,app 有 60 秒重试窗口,
正常会自己恢复。超过 60 秒还在重试就是数据库配置错了。

### 磁盘满了

```bash
docker system df
docker system prune -af --volumes      # 清掉不用的镜像和构建缓存
sudo truncate -s 0 /var/lib/docker/containers/*/*-json.log   # 清空容器日志
```

审计表会自动清理(默认保留 7 天,见 `SECGUARD_AUDIT_RETENTION_DAYS`)。
