## 版本二:三条(推荐,大多数简历用这个)

> **SecGuard — 高性能安全审计引擎**(C++20 / CMake / MySQL / Redis / Docker)
>
> - 手写 **AC 自动机**(Trie + BFS 建 fail + 转移补全)做多模式实时匹配:
>   252 条特征下比朴素逐串匹配快 **54 倍**(2 核云服务器实测:
>   136,185 次/秒 vs 2,503 次/秒;特征数 ×5 时 AC 耗时仅 ×1.0),
>   验证方式为 **2 万次随机对拍 + ASan/UBSan**,零差异零报错
> - 设计**无锁 MPSC 队列 + 后台批量落库**的审计管道:
>   相比同步写库吞吐从 281 提升到 **36520 QPS(130 倍)**
> - 基于 Redis + Lua 实现**分布式限流/封禁/重放防护**(带单机降级),
>   并把封禁检查与令牌桶合并为一次 Redis 往返、连接改为线程局部,
>   压测驱动下吞吐从 20627 优化到 **35070 QPS(P99 15ms → 7.7ms)**
>
> - 上线后**用真实流量驱动改进**:被云凭据扫描器打了 33,821 次 / 7.5 小时,
>   先确认敏感路径探测返回 200 的次数为 **0**(零泄漏),再据此补 18 条规则、
>   把被封 IP 的审计记录降采样(全库 79% 是无信息的封禁拒绝)、
>   把 200 个 IP 的同类探测聚合成一条告警
>
> *整套服务 Docker Compose 一键部署(nginx/app/mysql/redis,约 420MB 内存);
> GitHub Actions 在干净 Ubuntu 上从零编译 + 对拍 + 单测 + 真库 DAO 全绿。*

## 版本四:项目 A(绕过评测 + 归一化层,单独占一段时用)

> **SecGuard 检测引擎加固 — 绕过评测与归一化层**(C++20)
>
> - **先量化再改**:自建 169 条标注语料(39 条基线 / 82 条变形 / 48 条正常,
>   覆盖 37 种绕过手法),用"基线命中、变形漏掉"作为绕过的严格定义,
>   测出原引擎在编码变形上的漏报率 **61.0%**(根因:检测链路对 QUERY/BODY 不解码)
> - **设计双遍检测**:"原始遍(零回归)+ 归一化遍(百分号/实体/JS 转义解码、
>   块注释折叠、空白压缩、NUL 剔除)"取并集,漏报率降到 **6.1%**,
>   误报仅 **+1.9pp**(其中 8/9 条是原有规则过宽的存量问题)
> - **归一化的收益是"收敛"而不是"猜"**:把无穷多种编码变形收敛成有限形状,
>   一条规则即可覆盖整族(`java\nscript:` / `java\tscript:` / `java%20script:`
>   → `java script:`);代价 **+0.37 µs/请求**(按 3.6 万 QPS 约 1.4% 单核)
> - **规则分级(BLOCK/ALERT)**:把"检出"和"处置"拆成两层,5 条超宽规则降为
>   `ALERT`(仍然记录、仍然进 AI 分析,只是不返回 403);正常样本
>   **误拦截 21.2% → 3.8%**、攻击拦截**零损失**(有逐条降级代价清单佐证);
>   ALERT 不计入封禁计数,避免"博客提到 select 就把作者封了"
> - **与 OWASP CRS 4.30 横向对比**(同一套语料、同一份线上报文、CRS 默认 PL1
>   未调参):纯编码类 35 条**两家全平**(说明方法达到工业基线);语义等价类
>   CRS 强 4 条(`or 2>1`、`top['al'+'ert']`、base64);正常流量误拦
>   **4.5% vs 15.9%**;并主动标注两处不可比的口径(path 被 nginx 归一化、
>   XSS 基线为单标签无利用代码)

|---|---|

| 130 倍 | 同一条件下:异步队列 vs 每请求同步 INSERT |
| 35070 QPS | 合并 Redis 往返 + 线程局部连接后的多轮中位数 |

## 不要写进简历的(会被问穿)

- ❌ "十万 QPS" —— 没在目标配置上测出来
- ❌ "零误报" —— 没有误报率数据,229 条手工特征一定会有误报
- ❌ "AI 智能识别准确率 95%" —— 没有标注数据,没算过
- ❌ "支撑千万级流量" —— 没做过
- ❌ "经过大规模真实攻击考验" —— 一共就 3.3 万次、一个主要来源,
  而且明确知道是凭据扫描不是 APT。**说清规模反而加分,夸大立刻掉分**
- ❌ "误报率低于 X%" —— 真实流量下没有标注,算不出来
- ✅ 可以写"LLM 分析层含置信度过滤与人工纠错闭环" —— 这是做到的功能

## 面试里最值钱的一段(建议背下来)

> "这项目最有意思的不是我写了什么,是它上线之后发生了什么。
>
> 第二天进来 3.3 万次请求,来自一个专门扫云凭据泄露的工具 —— 它找
> `.env`、阿里云配置文件、`secrets.properties` 这些东西。
>
> 我做的第一件事不是加规则,是先去查**有没有漏出去的**。查法是所有敏感路径
> 探测里返回 200 的次数,结果是 0。
>
> 然后我把这一晚的数据当成一次免费的渗透测试复盘,它告诉我三件我坐着想
> 不到的事:
> 一,我的规则库对 `.env` 有覆盖,但 `alibabacloud.yaml`、`oss.json`
> 这些全部返回 404 —— 404 也拿不到文件,但它记成 PASS、不计入封禁,
> 攻击者可以一直扫。补了 18 条。
> 二,被封禁的 IP 继续刷,每个请求都写一条审计,占了全库 79%,全是
> 没有信息量的记录。改成每分钟最多记一条。
> 三,218 条告警里 191 条是同一件事,来自 200 个不同 IP —— 分布式扫描。
> 逐条告警的结果是真正高危的 6 条 SQL 注入被彻底淹没。改成聚合成一条。
>
> 这三个改动都不是我计划中的,是真实流量逼出来的。"

这段的作用:证明你不只是"能写代码",而是**能根据真实反馈判断优先级**。
面试官最怕的是"只在本地跑过 demo"的人。
